# ADR-0002: A lean backend with optional n8n orchestration

Date: 2026-10-06 · Status: Accepted for MVP

The requirements recommend Python/FastAPI, SQLite and thin n8n orchestration. The existing repository already has a direct SQLite repository and partial Python processing pipeline.

We retain these foundations. n8n calls a private scheduled-job endpoint; the backend owns Gmail access and SMTP as well as processing, ensuring checkpoint and delivery handling are identical in Docker, the CLI, tests and n8n. Unlike the proposed Gmail-node forwarding variant, raw email does not enter n8n execution data. The built-in scheduler provides a one-component fallback.

SQLite's standard library driver supplies transactions, indexes and a schema-version migration without an ORM or migration service. SQLAlchemy/Alembic are deferred until schema complexity or another database justifies them. The single-mailbox scale does not require Redis or PostgreSQL, so those unused starter containers are removed.

Hosted AI is an opt-in adapter. Disabled AI yields deterministic, conservative digests. Demo mode uses synthetic production-package data with no credential requirements; a mock AI can exercise the analysis path without a network.

Daily interval snapshots and durable delivery claims prioritize avoiding automatic duplicate emails. SMTP ambiguity requires explicit operator reconciliation; claiming exactly-once external delivery would be incorrect.
